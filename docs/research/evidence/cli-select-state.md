## Conventions used in the tables

- The edit: `order_totals` goes from `ORDER_TOTALS_ORIG` to `ORDER_TOTALS_EDIT` in `scripts/evidence/lib.sh`, which adds `max(amount) as biggest`. Before the edit, `order_totals` has 6 lineage rows. After a refresh it has 8, including `biggest <- stg_orders.amount copy` and `biggest <- stg_orders.customer_id scan` (s1a `11-plus-name-l1`).
- "Refreshed" means the next `show --info column_lineage` has `order_totals` rows that include `biggest`.
- The argv column is `result.json`'s `argv`. `<P>` is the project directory, `<dbt>` the binary and `<OUT>` the run's output directory, which holds `targets/<label>` copies made by `save_target`.
- env+: `SO` is `FUSION_POWER_USER_SCHEMA_ORIGIN=local`, the only variable beyond the base environment in every experiment here. The base environment is `HOME`, `PATH`, `TERM=dumb`, `DBT_PROFILES_DIR=<P>`, `DBT_ENGINE_PROFILES_DIR=<P>` and `DBT_SEND_ANONYMOUS_USAGE_STATS=false`.
- "view N rows: model n@t": the rows of `show --info column_lineage --output json`, grouped by child model, with the distinct `ingested_at` values as local time (UTC−07:00) and "(biggest)" when a `biggest` row is present. `--inline read_parquet(...)` steps are summarised the same way, per parquet file.
- W1 is this line, verbatim, as printed on stderr (it is followed by `Did you mean "orders"?` and `LINE 1: DESCRIBE "probe"."main"."stg_orders";`):
  `[warning] [RemoteError (dbt1014)]: Failed to download model schema for 'model.lineage_probe.stg_orders'. Setting 'static_analysis' to off. Skipping analysis for 'model.lineage_probe.order_totals': Catalog Error: Table with name stg_orders does not exist!`
- W2 is the same line with `download deferred model schema` in place of `download model schema`. "×2" means it was printed twice.
- "files:" lists changes since the previous step's `files-after.txt` to lineage-related paths only: `IS` = `target/info_schema/v1/dbt.column_lineage.parquet` (with the first 8 hex digits of its sha256), `pm/compile/…` = `target/private/metadata/compile/{column_lineage,schemas}/…`, `pm/warehouse/…` = `target/private/metadata/warehouse/…`, and `index/…` = `target/private/index/{.fusion_state.json,dbt.column_lineage.parquet}`. `+` means added, `~` changed and `-` removed. After `reset_target`, changes are counted from an empty `target/`. The full listings with sizes, mtimes and sha256 prefixes are in each step's `files-after.txt`.
