# Scope editor services to Declared Projects

Fusion Power User will automatically serve a workspace-folder root containing `dbt_project.yml`, while explicit folder-scoped project paths handle nested or otherwise ambiguous layouts. Each Declared Project owns one LSP process; dbt remains responsible for parsing its packages, cross-project references, and ignore rules. A Dependency Project does not receive independent editor services unless the user also declares it as a project, preventing recursive discovery from registering copied packages or unrelated dbt trees.

**Amended 2026-10-13:** a Declared Project also comes from a `file`-scheme document opened inside an enabled workspace folder. Only documents in the `sql`, `jinja-sql` and `yaml` language modes declare one, and only in a trusted workspace. The walk runs only upward from the opened file, to the nearest directory at or below the folder root that holds `dbt_project.yml` or `dbt_project.yaml`. A file under `node_modules`, `dbt_packages`, `dbt_internal_packages` or `target` declares nothing, and the walk does not reach other packages or trees, so this is not recursive discovery. A project declared by an opened file lasts until the window reloads. It is removed sooner when its folder leaves the workspace or the folder is disabled. A Declared Project whose root lies strictly inside another Declared Project's root is excluded from the outer project's language server, for `file` URIs only, so a nested project's files reach only its own server. Documents with other schemes, such as `untitled:` and `git:`, declare nothing.
