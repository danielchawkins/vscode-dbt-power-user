# Pin contributor tooling with mise and Just

This repository pins its Node runtime, contributor CLIs, and a dbt Fusion binary in `mise.toml` with a committed `mise.lock`, and exposes every workflow through Just. The root `justfile` owns repository composition and delegates webview-specific work to `webview_panels/justfile`; package scripts expose package-local operations and required npm or VS Code lifecycle hooks. `just check` is the only gate; CI, the Lefthook pre-push hook, and humans all call it. It validates a clean `mise install --locked --dry-run` so missing platform artifacts fail locally before CI. dprint and rumdl own Markdown, shfmt and ShellCheck own shell scripts, and ESLint and Prettier keep TypeScript, JavaScript, JSON, and CSS. Lefthook replaces Husky and lint-staged because staged-file scoping reads more clearly in one declarative file. These conveniences are borrowed from the `finance-pipelines` consumer repository, which also supplies the vendored skills under `.agents/skills/`; its uv, Python, Snowflake, Dagster, and multi-root workspace conventions are deliberately not imported into a TypeScript extension repository. Pinning Fusion here is a development-environment decision and does not weaken the product boundary: the shipped extension remains tool-manager-neutral, resolving `dbt` from `PATH` or an explicit path setting, and neither the extension nor its tests may invoke mise. The lock records checksums for both supported macOS Fusion archives, and `just check` validates both npm lockfiles against HTTPS public-registry URLs and integrity hashes.

The packaged-VSIX smoke runs on pinned VS Code and Cursor hosts. Cursor comes only from its immutable production URL (`https://downloads.cursor.com/production/<commitSha>/darwin/arm64/Cursor-darwin-arm64.dmg`), recorded with its SHA-256 in `scripts/smoke/pins.env`; `scripts/smoke/fetch-cursor.sh` fails on a checksum mismatch and has no skip path. The resolve API is called only when advancing the pin, through `scripts/smoke/resolve-cursor-pin.sh`, because it serves `releaseTrack=latest` only (a version-specific track returns no link) and older archives may return HTTP 403. After advancing, confirm the new app's `out/cli.js` still accepts `--skip-onboarding` and `--suppress-popups-on-startup`, which let the smoke run without credentials; Cursor's background authentication errors are not a failure.
