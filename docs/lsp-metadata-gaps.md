# Parse-owned metadata fields

The fields below reach consumers only from `dbt parse` and `manifest.json`, because no dbt Fusion 2.0.6 language server command returns them at project grain. Every other field of `ParsedManifest` (`src/dbt_integration/domain.ts`) can come from the language server: the node set and each node's `unique_id`, name, resource type, package, `original_file_path`, materialization, access and group; `graphMetaMap.parents` and `.children`, inverted from `depends_on`; `modelDepthMap`; the adapter type and project name. The split, the merge and the migration rule are in [One seam](refactor/quality-and-lsp-plan.md#one-seam-the-composite-producer-d8); the evidence is [`lsp-capabilities-fusion-2.0.6.md`](research/lsp-capabilities-fusion-2.0.6.md). Until the composite producer lands, `ManifestMetadataSource` (`src/metadata/manifestMetadataSource.ts`) still supplies every field.

A row leaves this list when a newer Fusion version returns the field for every node of its kind in one request on both captured projects. The row names the map key that `FIELD_OWNERS` will use.

| Field                                                                                                  | Manifest map                                       | Consumers                                                                                                                                    | Fusion 2.0.6 result                                                                                                                          |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Node description                                                                                       | `nodeMetaMap`                                      | docs editor (`docsEditPanel.ts`, `docGenService.ts`), lineage details drawer (`lineagePanel.ts`, `dbtLineageService.ts`), Documentation tree | `dbt.listNodes` nodes have no `description`; hover on `ref()` renders column descriptions as Markdown only                                   |
| Columns: names, descriptions, `data_type`, `meta`, column constraints                                  | `nodeMetaMap`                                      | docs editor, `docGenService.ts`, `dbtTestService.ts`, lineage drawer and column lists, Documentation tree, `projectCodegen.ts`               | No columns in `dbt.listNodes`. `dbt.getCurrentNode` returns names and types for one model per request, types only in strict, no descriptions |
| `meta` and tags                                                                                        | `nodeMetaMap`, `sourceMetaMap`                     | lineage drawer                                                                                                                               | Not in any command result                                                                                                                    |
| Relation: `database`, `schema`, `alias`, `relation_name`                                               | `nodeMetaMap`                                      | model tree labels (`modelTreeviewProvider.ts`), lineage table labels (`dbtLineageService.ts`), foreign-key resolution                        | Not in `dbt.listNodes`. `dbt.getCurrentNode` returns `database` and `schema` for one model per request                                       |

| Test metadata                                                                                          | `testMetaMap`                                      | `runTest.ts`, `dbtTestService.ts`, lineage drawer, relationship overlay (`lineagePanel.ts`)                                                  | Generic tests absent, as above; singular tests carry identity only                                                                           |
| Macros                                                                                                 | `macroMetaMap`                                     | test generation (`dbtTestService.ts`)                                                                                                        | `resource_type:macro` gives `No nodes found`; no command lists macros                                                                        |
| Doc blocks                                                                                             | `docMetaMap`                                       | docs editor (`docsEditPanel.ts`)                                                                                                             | `resource_type:doc` gives `No nodes found`                                                                                                   |
| Metrics                                                                                                | `metricMetaMap`                                    | no feature outside `src/projects/manifest.ts`                                                                                                | No metric nodes                                                                                                                              |

| Unit-test target model                                                                                 | `unitTestMetaMap`                                  | test listing (`dbtTestService.ts`)                                                                                                           | Unit-test nodes carry identity and `depends_on`; no `model` field                                                                            |

| Constraint edges and model constraints                                                                 | `graphMetaMap.parents`, `.children`; `nodeMetaMap` | lineage hides `edgeType: "constraint"` edges (`dbtLineageService.ts`); relationship overlay                                                  | `depends_on` has no edge type, and no command returns constraints                                                                            |

Two parse outputs are not `ParsedManifest` maps and stay outside the port: configuration errors that stop the project loading (an unknown target, an unset `env_var` in `profiles.yml`), which the server does not report and `ProjectErrors` reads from `dbt parse`; and raw and compiled SQL and `compiled_path`, which no feature reads from the manifest.
